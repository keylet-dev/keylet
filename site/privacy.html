Keylet Privacy Policy

Effective date: November 17, 2026

1. Zero Telemetry & Zero Data Collection by Keylet

Keylet does not operate any backend servers, analytics services, crash-reporting pipelines, or advertising trackers. We do not collect, sell, rent, or transmit your personal data, master password, vault entries, or browsing history to Keylet or any third party.

2. End-to-End Client-Side Encryption

All encryption and decryption happen locally on your device using Web Crypto / standard cryptographic primitives (PBKDF2-SHA256 or Argon2id key derivation and AES-256-CBC with HMAC-SHA256 Encrypt-then-MAC). Network requests are sent exclusively to the Bitwarden or self-hosted Vaultwarden server URL you explicitly configure.

3. Local Storage & Session Memory

  • Browser Extension: Stores only your encrypted vault snapshot and account configuration in browser extension storage. Decrypted keys are kept strictly in ephemeral session/worker memory and cleared when locked.
  • Android App: Stores encrypted vault data locally and uses Android KeyStore / BiometricPrompt for optional quick unlock.

4. Permissions Explanation

  • storage & alarms: Cache encrypted vault data and enforce auto-lock timers.
  • activeTab & host permissions: Match credentials to the active site domain and offer inline autofill or credential saving when you submit a login form.
  • clipboardWrite: Copy usernames, passwords, TOTP codes, or SSH keys upon your explicit action.
  • contextMenus: Provide right-click autofill actions.
  • Website Icons: Login favicons are requested from your configured Bitwarden/Vaultwarden server's icon proxy (/icons/<domain>/icon.png) when available.

5. Contact

Keylet is open source at github.com/keylet-dev/keylet. Questions or security reports can be filed via GitHub Issues.
